# SCAN WIDGET (KIRA) — READ THIS FIRST

**The master handover pack lives in the ERP repo: `hug-and-test-39a2bffb/docs/HANDOVER.md`.**
Read it fully before changing anything here — this widget is a thin client;
all pricing, catalog, AI analysis and order logic live in ERP edge functions.

## This repo in one page

- React + Vite, deployed at scan.tenxix.com. Push to `master` → Vercel
  auto-deploys. Embedded on landing pages as an iframe popup (snippets are
  generated by the ERP Widget Builder — never hand-write embeds).
- TWO backends chosen at runtime (`src/constants.ts`): default = ERP project;
  `?scan=kira` = the separate Kira Mirror project (own catalog/prices —
  known strategic issue; unification is planned, master pack §9 item 11).
- URL params ARE the contract: `ref` (config + buyer attribution — required),
  `product` (product mode: instant verdict + recommendations), absent product
  = GENERAL mode (analysis-first → floating CTA → formulation animation +
  AM/PM regimen → reveal), `cmp` (campaign attribution stamped on orders).
- Flow state machine in `src/App.tsx`; result rendering in
  `screens/ResultScreen.tsx` (full app-parity report via
  `components/SkinReportSection.tsx`, falls back to compact view when the
  backend omits the report). All API responses are sanitized in `src/api.ts`
  — keep every render path trusting only sanitized shapes.
- ERP-side functions this widget calls: get-scan-widget-config,
  analyze-skin-scan (Sonnet, anchored rubric), generate-scan-regimen (Haiku,
  fail-soft), submit-scan-order (server-priced; one main item rule),
  log-page-event. Deploy them with `--no-verify-jwt` ALWAYS.
- Product catalog control: ERP Products module — `scan_widget_eligible`
  checkbox, `skin_concern_targets`, `ingredients` jsonb power the AI matching
  and the Know More modal.
- Learning loop: every scan writes its full report to ERP `scan_events`;
  orders carry `scan_session_id`. Do not remove those fields from calls —
  they feed the intelligence views.
